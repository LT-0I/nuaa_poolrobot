# 沿边行走问题诊断报告 · move_controller

> **对象**：[`sonar_slam/src/move_controller.cpp`](../sonar_slam/src/move_controller.cpp)（@ `main`，已确认最新）
> **目标行为**：贴右墙、距墙固定值（**2m，可调**）、绕池一圈、拐角只左转。
> **症状**：每次拐角后机头不回正、**偏向右墙**，于是该段**越走越近**，最终前向传感器把右墙当前障 → 提前拐弯 → 整圈节奏全乱。

> 链接均指向本仓库源码对应行，点击可直接对照代码。

---

## 结论先行

症状与代码完全对得上。**头号根因 ＝ 沿边根本没有「距墙距离」控制环**，只有「平行度 / 航向」控制；任何残差航向都会让距墙距离单调漂移、无回正力。拐角的左转又靠**慢速（0.83Hz）且会读到旧值**的右侧超声判「平行」就停 → 常常没转够、机头朝墙；随后直行段把这个**错航向当成「直」锁死**、能发现朝墙的超声修正又太弱。三者叠加 = 越拐越往墙里钻。

## 3. 根因（按数据流，每条带代码证据）

### 🔴 根因① 控制器：根本没有「距墙距离」控制环（头号）

- 距墙目标参数 `config_wall_align_` 是**死参数**：全代码只出现 3 次——构造初始化 [L25](../sonar_slam/src/move_controller.cpp#L25)、加载 [L68](../sonar_slam/src/move_controller.cpp#L68)、打印 [L77](../sonar_slam/src/move_controller.cpp#L77)，**从不参与任何控制计算**（默认值还是 1.0，不是 2m）。
- 直行段纠偏（[L1156–1273](../sonar_slam/src/move_controller.cpp#L1156)）的转向输出 `current_angular_correction` **只**由两个量决定：① `relative_theta = total_yaw_change`（odom 累积航向，[L1157](../sonar_slam/src/move_controller.cpp#L1157)）；② `parallel_error = 右后 − 右前`（平行度，[L1179](../sonar_slam/src/move_controller.cpp#L1179)）。
- **绝对距墙距离 `(右前+右后)/2` 从未用于纠偏。** 右侧两路只拿去算「前后差(平行)」，从不算「离墙多远」去拉回目标。

> **⚠ 为什么这是越走越近的元凶**：墙跟随的本质是**距离闭环**（d→目标）。现在只闭了「平行/航向」。理想全平行时距离才恒定；可现实里只要有**一点点**残差航向（拐角后必然有），距离就以**恒定斜率单调**逼近或远离墙，**没有任何力把它拉回 2m**。这正是「走着走着越来越近」的数学签名。

### 🔴 根因② 控制器+传感器：拐角左转把航向留偏了（「偏右」）

拐角左转序列（[L1018–1093](../sonar_slam/src/move_controller.cpp#L1018)）：

- 先**开环**盲转：`angular.z=0.25` 一直转到 odom 角度到 **70°**（[L1038–1042](../sonar_slam/src/move_controller.cpp#L1038)）。
- 过 70° 后改判**平行**：右侧 `|右后−右前| < 0.025` 就停（[L1066](../sonar_slam/src/move_controller.cpp#L1066)）；兜底 8s 超时（[L1032](../sonar_slam/src/move_controller.cpp#L1032)）或数据无效时转到 88° 停（[L1079](../sonar_slam/src/move_controller.cpp#L1079)）。

> **⚠ 关键缺陷：判平行用的是「会过期的旧值」。** 右侧超声**每路只 ~0.83Hz（1.2s 刷一次）**，而这个判停循环跑 **20Hz**（0.05s）。循环读的是缓存字段 `wall_sensors_.ultra_right_*`，只有 `ultraCallback` 在 1.2s 才更新一次 → 同一个旧值被复算约 24 次。于是 `|误差|<0.025` 很可能在机器人**还没真转到平行**时、用一帧旧快照就触发 → **提前停 = 没转够 = 机头朝墙（偏右）**。刚拐过来时右侧两路还可能没稳定锁到新墙（看到角落/旧墙/超量程），平行误差更不可信。

拐完还会调一次 [`alignToRightWallOnly()` L1099](../sonar_slam/src/move_controller.cpp#L1099)（定义 [L1406](../sonar_slam/src/move_controller.cpp#L1406)）——但它**同样只把右后/右前拉到相等**（`TOLERANCE=0.035m` [L1497](../sonar_slam/src/move_controller.cpp#L1497)），**也不管离墙多远**。所以两道工序都只保证「平行」、都不纠正「横向位置」，机器人可以「平行但已经贴得比 2m 近」。

### 🔴 根因③ 控制器：错航向被 odom 锁死、超声纠不回来

- 拐完**把 `total_yaw_change` 重置为 0**、`last_theta=当前odom航向`（[L1103–1104](../sonar_slam/src/move_controller.cpp#L1103)）——即**把拐弯后这个偏的航向当成了新的「直」(零基准)**。没有任何绝对航向参考、也没用超声平行来定这个零。
- 之后直行纠偏（[L1165–1261](../sonar_slam/src/move_controller.cpp#L1165)）四个分支是**互斥 if/else**：odom 偏出 ±0.02rad 就强力拉回零基准（置信度 0.8–1.0、增益 ×1.5–2.0，[L1205](../sonar_slam/src/move_controller.cpp#L1205)/[L1213](../sonar_slam/src/move_controller.cpp#L1213)/[L1221](../sonar_slam/src/move_controller.cpp#L1221)）；**只有 odom≈0 时**才轮到唯一能发现「机头朝墙」的超声分支，而它是**最弱档**（置信度 0.3、幅值 ±0.08 → 实际 `±0.08×0.3≈±0.024 rad/s`，[L1232–1242](../sonar_slam/src/move_controller.cpp#L1232)、[L1250](../sonar_slam/src/move_controller.cpp#L1250)）。
- 净效果：拐角留下的**错航向成了被死守的零点**；机器人一旦想往正确方向回，立刻被 odom 当成「偏」强力拽回错零点；能识别朝墙的超声修正太弱、且只在 odom≈0 时才生效 → **纠不回来**。
- 叠加 odom 本身的问题：`current_pose_.theta` 来自 `/wheel_odom` 姿态，而驱动里该姿态是**纯陀螺积分**（`base_pose.theta += imu_wz·dt`，无融合/无绝对参考、会漂）→ 这个「零基准」本身还在缓慢漂移。

> **三因合一的闭环故障**：拐角(②)留下机头朝墙的航向 → odom(③)把它锁成「直」→ 没有距离环(①)去把横向位置拉回 → 机器人保持朝墙、**匀速逼近右墙** → 距墙 <1.5m 时**前向传感器(前左/前右, min<1.5m, 连续3次, [L996–1003](../sonar_slam/src/move_controller.cpp#L996))**把右墙当前障 → 提前触发下一次拐弯 → 整圈节奏全乱。

## 4. 修改方案（按数据流，设计级；⚠ 待确认后再动代码）

### 传感器层

| # | 改什么 | 为什么 |
|---|---|---|
| **S1** | **遮挡定标锁死 4 路物理映射**（用 ultra_logger 30s 伸手遮挡） | 前置项：方案全靠 `data[2]/[3]=右前/右后` 为真。驱动请求侧标号与此有历史冲突（§5-A）；定标一次性坐实。 |
| **S2** | 右侧两路加**新鲜度门**（值变才进控制）+ 跳变剔除 + 量程门 + 中值；显式输出 `d=(右前+右后)/2` 与 `e_par=右后−右前` 并校验有效 | 每路真实 0.83Hz（话题 20Hz 是零阶保持的假象）。任何「判停/判平行」都不能拿旧快照在 20Hz 循环里反复触发（根因②）。 |

### 控制器层（核心）

| # | 改什么 | 为什么 |
|---|---|---|
| **C1** | **补距墙距离环**：复活 `config_wall_align_`（默认改 2.0m）。外环 PD 让 `d→d_target` 输出一个航向参考，内环保平行：`heading_cmd = Kd·(d − d_target) + Kpar·e_par`（离墙远→朝墙偏一点、离墙近→离墙偏一点） | **直接消灭根因①**，给横向位置一个回正力。把「只平行」升级成「真墙跟随」的关键一步。 |
| **C2** | **航向「直」的定义改用超声**（`e_par=0 且 d=target`），不要把拐弯后的瞬时 odom 当零基准；odom（裸陀螺、会漂）只做**短时内环阻尼**，不做长期基准 | 消灭根因③：不再把错航向锁死，也不被漂移污染。 |
| **C3** | **拐角终止判据改双条件多帧**：转够 ~90°(odom 粗定) **且** 右侧超声「**新鲜**」读数连续多帧满足平行 + 距离合理，才算转完；否则继续 | 消灭根因②的「旧值提前停」。 |
| **C4** | 统一 odom / 超声**优先级**（超声为主、odom 辅助去噪），去掉互斥分支里「odom 强、超声弱」的失衡 | 让能看见墙的信号说了算。 |

### 执行器层

| # | 改什么 / 注意 | 为什么 |
|---|---|---|
| **A1** | 整定增益按**经驱动 ×6.4 后**的真实角速率标定（move_controller 发 0.25 → 实际 1.6 rad/s；纠偏 0.08/0.12 → 0.51/0.77；限幅 0.30 → 1.92）。建议控制器侧按物理 ω 设计、明确换算 | 现在所有角速度数值的「真实大小」都被悄悄放大 6.4 倍，整定容易过冲。 |
| **A2** | **看门狗交互**：拐角里有 `sleep(1.5)`（[L1014](../sonar_slam/src/move_controller.cpp#L1014)）等「发一条等一段」的写法。若给驱动加 0.5s 看门狗（main 目前还没有），这类缺口会被打断 → 改成持续发 /cmd_vel 或调大 timeout | 避免部署看门狗后沿边被误停（时序坑）。 |

## 5. 实施前需确认 / 提供的

- **A（前置·重要）**：**遮挡定标确认 `data[2]/[3]` 确为右侧前/后超声。** 已确认意图映射 = data0前左 / 1前右 / 2右前 / 3右后；但核验时发现**驱动请求侧的通道标号与之冲突**（历史三方冲突）。整套距离+平行环都依赖 data[2]/[3] 是右侧——若实际是别的传感器，方案全错。定标一次锁死即可。
- **B**：目标距墙 `d_target=2m`（可调）——确认就用它，把 `config_wall_align_` 默认改 2.0。
- **C**：直行微调是否允许**双向**（含右微调，负 angular.z）？严格「只左转」通常指大拐弯；微调双向才稳，建议保留双向微调、只把大转弯限定为左。
